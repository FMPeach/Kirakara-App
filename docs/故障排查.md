# 故障排查

遇到问题时，先从仓库根目录重新运行失败的 `flutterw` 命令，并保留第一处有效错误。
日志可以包含命令、错误码和组件版本，但不要公开 Cookie、Token、剪贴板内容或真实媒体
地址。

## PowerShell 无法运行脚本

Kirakara-App 使用 PowerShell 7.2 或更新版本。先确认 `pwsh` 可用：

```powershell
pwsh --version
```

请不要用 Windows PowerShell 5.1 代替，也不需要为了项目永久修改系统 `PATH`。

## 找不到 Kirakara Show

Windows 版需要由 Kirakara Show 提供 `libshow_host.dll`。复制本地配置模板：

```powershell
Copy-Item .\config\kirakara.local.example.json `
  .\config\kirakara.local.json
```

将 `windows.showHostDll` 改为本机 Show 构建产物的绝对路径。路径可以位于仓库外，也可以
包含中文和空格；配置文件只在当前电脑生效，不会提交到 Git。更新 Show 后如果 DLL 路径
发生变化，也要同步修改这里。

如果仍然失败，请确认目标确实是 Windows x64 DLL，而不是导入库、其他架构的产物或已经
被删除的旧构建目录。

## Engine 下载或校验失败

项目通过 `engine/prebuilt.lock.json` 选择预编译 Engine，并逐项校验大小、SHA-256 和
包清单。网络中断可以直接重试原命令；出现哈希、清单或 ABI 不匹配时，不要改锁文件、
伪造缺失文件或复制其他版本的 DLL。

可以先查看当前选择：

```powershell
.\flutterw engine status
```

若本地安装确实损坏，可只清理对应模式后重试：

```powershell
.\flutterw engine clean debug
```

把 `debug` 换成实际使用的 `profile` 或 `release`。这不会清理其他项目的 Flutter 环境。

## 修改 Engine 源码时失败

普通 App 开发不需要下载或编译 Flutter Engine 源码。只有修改 Windows Embedder、合成器
或其他 Engine 层能力时，才使用源码流程：

```powershell
.\flutterw engine doctor --from-source
.\flutterw engine prepare debug --from-source
```

源码构建建议把仓库放在较短的纯英文路径，例如 `D:\Kirakara-App`，以避开部分上游构建
工具对中文路径和超长路径的限制。完整流程见
[Flutter Engine 开发指南](Flutter-Engine开发指南.md)。

## 输入法或手写资源缺失

Engine、输入法运行库、Rime 数据和手写模型是独立资源。`flutterw run` 或 Windows 构建会
在开始编译前检查它们；缺少哪个资源，应按错误信息准备对应的已校验包。不要用来源不明
的 DLL 或模型替换，也不要通过关闭手写功能掩盖资源问题。

维护输入法来源、许可证或数据包时，请阅读
[third_party 说明](../third_party/README.md)和[原生依赖说明](../native/README.md)。普通界面
开发不需要运行这些维护脚本。

## 清理项目

先关闭正在运行的 App 和构建进程，再按需要选择清理范围：

```powershell
.\flutterw clean
.\flutterw engine clean debug
```

第一条清理 Flutter App 构建结果；第二条只清理指定模式的 Engine 安装和选择。只有需要
彻底重建当前仓库的隔离环境时才运行：

```powershell
.\flutterw engine purge
```

`purge` 会删除当前仓库 `.kfe` 中的 SDK、源码、下载缓存和构建结果，但不会影响其他仓库
或系统 Flutter。执行前先保存尚未导出的 Engine 补丁和需要保留的诊断日志。

## 提交问题

如果问题仍然存在，请附上：

- 复现步骤和预期行为；
- Windows 版本、CPU/GPU 与显卡驱动版本；
- 使用的 Git commit；
- 第一处有效错误及其前后少量日志；
- 问题是否只出现在单屏、双屏或 Cast 模式。

画面、输入法和播放问题最好再附一张截图或一段短录屏。请先确认其中没有账号、Cookie、
媒体私链或其他隐私信息。
